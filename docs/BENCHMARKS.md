## 3. Per-snapshot (tick-to-signal) latency

One snapshot in, one signal out: what a live system pays per market update.

| Path | p50 | p99 | p99.9 | max |
|---|---:|---:|---:|---:|
| C only, `lob_obi_one` (TSC timed) | 16 ns | 317 ns | 547 ns | 1,699 us |
| C only, `lob_wobi_one` (TSC timed) | 21 ns | 62 ns | 81 ns | 1,854 us |
| Python -> ctypes -> `lob_obi_one` | 300 ns | 800 ns | 1200 ns | 1,853 us |
| Python -> ctypes -> `lob_wobi_one` | 1000 ns | 2700 ns | 11000 ns | 2,931 us |
| Legacy WOBI per tick (struct fill + call) | 7,200 ns | 19,100 ns | 94,802 ns | 7,287 us |

Timer overhead: TSC 17 ns (C rows). Python rows use `perf_counter_ns`, whose resolution here is 100 ns, so they are quantised to that step. Python figures are dominated by interpreter + ctypes marshalling, not by the kernel; C tail latencies (max) are OS preemption/interrupts.
